# Recover a small task from files

Experimental starter for repository owners and resuming contributors. This note
asks questions; the destination repository's policies and task grant supply the
answers. It grants no work and does not replace those owners.

Before acting, follow a short owner map supplied by the repository:

| Find | Recover |
| --- | --- |
| Governing instructions | Scope, authority order, permitted access and operations. |
| Task grant and acceptance owner | The exact authorized change, limits, completion evidence and consequential stop. |
| Current task state | Candidate identity, prepared work, checks actually completed, missing evidence and review disposition. |
| Working state | Baseline versus current changes, including staged, unstaged and untracked work where applicable. |
| Local handoff location | Durable restart context that points back to canonical authority and evidence. |

Keep these distinctions visible: a proposal suggests work; authorization permits
bounded work; an implementation prepares a candidate; verification supplies
observed check results; independent review supplies its own scoped findings.
Publication needs its own grant and evidence of actual execution. None of these
states implies the next one. Read historical records with current dispositions.

Report six answers with file references before resuming:

1. What exact edit is authorized, and what limits it?
2. What candidate is prepared, and what is actually verified?
3. Which required independent review is complete or missing?
4. Which unrelated work must be preserved?
5. What is the next permitted action, and where must work stop?
6. Which actions remain unauthorized?

Inspect evidence before inferring success. A missing result stays missing. If the
grant, candidate or acceptance criteria conflict or cannot be recovered, identify
the gap and stop the dependent action. A read-only recovery assignment reports
the next execution step without performing it.

Preserve unrelated work using the repository's own staging and preservation
rules. Do not clear dirty state just to make recovery simpler. Keep local restart
notes in repository-associated durable storage excluded from publication, as
chosen by its owner. Record candidate identity, completed evidence, unresolved
findings, next action and stopping reason. Local notes are noncanonical pointers,
not replacement authority or a backup. Preserve original evidence rather than
reconstructing lost observations.

For sharing, create synthetic examples. Exclude credentials, private paths,
trust material, real operational handoffs and private evidence. A destination
chooses its own commands, storage, telemetry and checks; no particular tool,
observation schema, model or domain contract is required by this starter.
