# Recover a small task from files

Use this handout when returning to a small task or handing it to someone else.
The destination repository's instructions and the human's task grant supply the
answers. This note grants no work or external access.

In Indelegible, start with [README.md](README.md#begin-one-useful-task) and
[AGENTS.md](AGENTS.md). Elsewhere, follow that repository's owners. An issue,
existing task note or current grant can hold the task context; no particular
filename or set of process records is required.

Before acting, find the owners of these answers:

| Find | Recover |
| --- | --- |
| Governing instructions | Recover the scope, authority order, permitted access and operations. |
| Task grant and acceptance owner | Recover the exact authorized change, limits, completion evidence and consequential stop. |
| Current task state | Identify the candidate, prepared work, completed checks, missing evidence and review disposition. |
| Working state | Distinguish baseline and current changes, including staged, unstaged and untracked work. |
| Local handoff, if needed | Find durable restart context that points back to canonical authority and evidence. |

Keep the states distinct. A proposal suggests work. Authorization permits bounded
work. An implementation prepares a candidate. Verification supplies observed
results. Independent review supplies its own scoped findings. Publication needs
its own authority and evidence of execution. None implies the next state.

Report six answers with references before resuming:

1. What exact edit is authorized, and what limits it?
2. What candidate is prepared, and what is actually verified?
3. Which required independent review is complete or missing?
4. Which unrelated work must be preserved?
5. What is the next permitted action, and where must work stop?
6. Which actions remain unauthorized?

For example, an edit may be prepared while its required check is still missing.
Report both facts and identify the next authorized check. Do not describe the edit
as verified merely because it exists. This illustrates the questions; it records
no experiment or observed recovery result.

Inspect evidence before inferring success. A missing result stays missing. Read
historical records with their current dispositions. If the grant, candidate or
acceptance criteria conflict or cannot be recovered, identify the gap and stop the
dependent action. A read-only recovery assignment reports the next execution step
without performing it.

Preserve unrelated work using the repository's own staging rules. Do not clear
dirty state to make recovery easier. Where a local handoff is needed, use
repository-associated durable storage excluded from publication. Record the
candidate, completed evidence, unresolved findings, next action and stopping reason.
Local notes are pointers, not replacement authority or a backup. Preserve original
evidence rather than reconstructing lost observations.

Keep credentials, private paths, trust material and real operational handoffs out
of shared examples. The destination chooses its own commands, storage and checks;
this starter requires no tool, telemetry schema, model or domain contract.
